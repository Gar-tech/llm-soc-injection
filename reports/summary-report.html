รายงานสรุปผล: Runtime Prompt Injection ต่อ LLM ที่ใช้คัดแยกมัลแวร์

โปรเจกต์ llm-soc-injection · ผลชุดแรกจากโมเดล llama3.1:8b · รันบน PC (RTX 4060 Ti 8 GB) · 10 พฤศจิกายน 2026

สรุปในย่อหน้าเดียว: เราฉีดข้อความแบบที่มัลแวร์สร้างตอนรัน (ชื่อ process, ไฟล์, registry, mutex, DNS) ลงในรายงาน CAPEv2 จริง แล้วให้ llama3.1:8b ตัดสินว่าเป็นมัลแวร์หรือไม่ ในรายงานที่โมเดลจับได้ถูกตอนยังไม่โดนโจมตี การโจมตีเปลี่ยนคำตอบเป็น benign ได้ 43% ของครั้งที่ทดสอบ เมื่อใช้ defense แบบ provenance tagging ลดลงเหลือ 21% ช่องทางที่ได้ผลที่สุดคือชื่อ process (68%) และ defense ไม่ช่วยกับ payload ที่ไม่ได้เป็นคำสั่งแต่ดูน่าเชื่อถือ (DNS)

1. คำถามของการทดลอง

  1. ข้อความที่มัลแวร์สร้างตอนรันและหลุดเข้าไปในรายงาน sandbox จะหลอกให้ LLM เปลี่ยนคำตัดสินจาก malicious เป็น benign ได้บ่อยแค่ไหน (Attack Success Rate, ASR)
  2. Defense แบบ provenance tagging (ติดป้ายว่าค่าที่มาจาก sample เป็นข้อมูลที่ไม่น่าเชื่อถือ ห้ามทำตาม) ลด ASR ได้เท่าไร

ใช้แค่ไฟล์รายงาน JSON ไม่มีการรันมัลแวร์จริง

3. ข้อค้นพบหลัก

  1. ข้อความตอนรันหลอกโมเดลได้จริงและบ่อย แค่ใส่คำสั่งไว้ในชื่อ process ก็เปลี่ยนคำตอบที่ถูกเป็น benign ได้ 13 จาก 19 รายงาน ทั้งที่ system prompt บอกไว้แล้วว่าข้อมูลในรายงานเป็นหลักฐาน ห้ามทำตาม
  2. การแบ่ง payload ได้ผลเมื่อทั้งสองครึ่งอยู่ด้วยกัน ฉีดครึ่งเดียวได้ 26% แต่ฉีดทั้งสองครึ่งลงรายงานเดียวกันได้ 53%
  3. Provenance tagging ลด ASR ได้ประมาณครึ่ง (43% → 21%) กลุ่มควบคุมที่ใส่ defense บนรายงานสะอาดเปลี่ยนเป็น benign แค่ 1 จาก 19 รายงาน การลดลงจึงไม่ได้มาจาก defense ทำให้โมเดลตอบ benign ไปหมด
  4. Defense ใช้ไม่ได้กับ benign framing payload ทาง DNS ไม่ใช่คำสั่ง แต่เป็นชื่อโดเมนที่ดูปลอดภัย การติดป้ายว่าห้ามทำตามจึงไม่ช่วย (32% → 37% ต่างกันแค่ 1 รายงาน) provenance tagging กันได้เฉพาะการสั่งให้ทำตาม ไม่ได้กันการโน้มน้าวด้วยหลักฐานปลอม
  5. โมเดลเล็กจับมัลแวร์จาก reduced reports ได้น้อย จับได้ 19 จาก 50 (38%) และจับได้แค่บางตระกูล: Lokibot 5/5, Qakbot 5/5, Trickbot 3/5, Ursnif 3/5, Zeus 2/5, njRAT 1/5 ส่วน Adload, Emotet, HarHar และ Swisyn จับไม่ได้เลย

4. ข้อจำกัด

  • ตัวอย่างเล็ก: n = 19 รายงาน ค่า ASR ต่อ payload ขยับประมาณ 5 จุดทุก 1 รายงาน ความต่างที่น้อยกว่าประมาณ 20 จุดไม่ควรอ่านว่าต่างจริง ช่วงความเชื่อมั่น 95% ของ ASR รวมประมาณ 35–51% (ไม่มี defense) และ 15–29% (มี defense) แต่คำนวณโดยถือว่าทุกการเรียกอิสระต่อกัน ช่วงจริงจึงกว้างกว่านี้
  • โมเดลเดียว: ผลนี้เป็นของ llama3.1:8b เท่านั้น โมเดลที่เก่งกว่าอาจได้ผลต่างไป
  • รายงานที่นับเข้าเอนเอียง: ทั้ง 19 รายงานมาจาก 6 ตระกูล ไม่ครอบคลุมอีก 4 ตระกูล
  • Reduced reports: ไม่มีฟิลด์ processes, network และ signatures ช่องทางชื่อ process และ DNS จึงมีแค่ payload บรรทัดเดียว ทำให้ payload เด่นกว่าในรายงานเต็ม
  • จำลองตำแหน่ง: ไม่ได้รันมัลแวร์จริง payload ถูกวางในตำแหน่งที่ค่าตอนรันน่าจะไปอยู่ ไม่ได้พิสูจน์ว่าทุก sandbox บันทึกค่าเหล่านี้ตรงตามนั้น

5. ขั้นต่อไป

  • รันโมเดลที่เก่งกว่า (เช่น Claude ผ่าน --backend anthropic) กับ 50 รายงานเดิม เพื่อดูว่าผลเกิดซ้ำหรือไม่ ค่า baseline 50 ไฟล์ด้วย Claude Sonnet 5.5 ประมาณ $0.5 รันเต็มประมาณ $9
  • สร้าง repo บน GitHub โดยไม่รวม .venv และไม่รวมไฟล์รายงานจนกว่าจะเช็ก license ของ dataset
  • เทียบ provenance tagging กับ defense แบบอื่น โดยเฉพาะกับ payload ที่ไม่ได้เป็นคำสั่ง เช่น benign framing
